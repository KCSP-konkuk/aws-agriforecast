# 분석 작업대 설계 — 흩어진 농산물 데이터를 한곳에서

작성 2026-10-04 · 상태: 설계 확정, 구현 시작

## 1. 왜 바꾸나

### 1.1 지금의 문제
- 홈(시세), 상세(도매 예측), 대시보드(인사이트), 커뮤니티가 따로 있어 **이 사이트가 누구를 위해 무엇을 하는 곳인지** 한 문장으로 말하기 어렵다
- 실무자가 가격을 분석하려면 데이터를 여러 곳에서 모아야 한다

| 데이터 | 어디서 | 주기 · 단위 |
|---|---|---|
| 소매가 · 도매가(중도매인) | KAMIS | 일별, 품목마다 단위가 다름 (1kg, 1포기, 100g …) |
| 경매가 · 반입량 | 농넷(가락시장) | 일별, 10kg 망·상자 단위 |
| 기온 · 강수 | 기상청 ASOS | 일별, 관측소별 |
| 환율 | 한국수출입은행 | 영업일 |
| 유가 | 오피넷 | 일별 |
| 물가지수 | KOSIS | 월별 |
| 검색 관심도 | 네이버 데이터랩 | 일별 상대값 |

주기·단위가 제각각이라 엑셀에서 날짜를 맞추고 단위를 바꾸는 손작업이 매번 필요하다.

### 1.2 목표 정체성
> **흩어진 농산물 시세·수급·날씨·거시 데이터를 한곳에 모아, 실무자가 직접 골라 비교하고 분석하는 도구**

화면 첫 문장도 이것으로 바꾼다. 예측과 자동 요약은 이 도구를 돕는 기능으로 자리 잡는다.

## 2. 사용자와 할 일

| 사용자 | 알고 싶은 것 | 지금 하는 일 | 작업대에서 |
|---|---|---|---|
| **소매상** (시장 상인, 반찬가게·식당 구매) | 언제 사고 얼마에 팔까 | KAMIS 소매가와 농넷 경매가를 따로 보고 감으로 판단 | 소매가·도매가 겹쳐 보기, 마진 추이, 도매가가 소매가에 반영되는 시차 |
| **도매상** (중도매인, 산지유통) | 물량·날씨가 경매가를 어떻게 움직이나 | 농넷 반입량·경매가, 기상청 날씨를 따로 확인 | 반입량·날씨·경매가를 한 화면에, 조건이 비슷했던 과거 찾기 |
| **KAMIS 직원** (조사·분석·보고) | 이번 가격 변동의 배경을 어떻게 설명할까 | KAMIS 가격과 물가·환율·기상을 엑셀로 합쳐 보고서용 그래프 작성 | 날짜가 맞춰진 통합 표 내려받기, 보고서용 그래프, 링크 공유 |

세 사용자 모두에게 공통 출발점은 **"품목 하나의 소매가 · 도매가 · 반입량"** 이다. 작업대 기본 화면을 이것으로 연다.

## 4. 분석 작업대

### 4.1 화면 구성
```
┌──────────────────────────────────────────────────────────────────────┐
│ 시작 템플릿 ▾ │ 기간 [1년|3년|전체|직접] │ 주기 [일|주|순|월] │ 공유 · 내려받기 │
├───────────────────────┬──────────────────────────────────────────────┤
│ 데이터 고르기           │ 차트 [시계열|산점도|3D 산점도|평행 좌표|시차 상관|지형도] │
│  🔍 검색               │                                              │
│  ▸ 가격 (소매·도매·경매) │            (선택한 차트)                       │
│  ▸ 수급 (반입량)         │                                              │
│  ▸ 기상 (관측소별)       ├──────────────────────────────────────────────┤
│  ▸ 거시 (환율·유가·물가)  │ 한 줄 해석 · 조건 걸기                            │
│  ▸ 관심도 (검색량)       ├──────────────────────────────────────────────┤
│ 고른 지표 (최대 8개)     │ 표 미리보기 (날짜 · 지표1 · 지표2 …)  [CSV 받기]     │
│  ● 양파 소매가  변환▾ 시차▾ ✕ │                                          │
└───────────────────────┴──────────────────────────────────────────────┘
```
모바일에서는 왼쪽 패널이 위로 접히고 차트·표가 아래로 쌓인다.

### 4.2 고르기 — 데이터 목록
- 분류(가격 · 수급 · 기상 · 거시 · 관심도)와 검색으로 고른다. 지표마다 **출처 · 단위 · 주기 · 기간(시작~마지막 날)** 을 보여 준다
- 한 번에 최대 8개. 고른 순서대로 색이 정해지고, 지울 때 다른 지표 색은 바뀌지 않는다
- 목록은 API(`/api/series/catalog`)에서 받는다 — 화면 코드에 품목·지표 이름을 두지 않는다

### 4.3 맞추기 — 주기 · 변환 · 시차
| 항목 | 선택지 | 규칙 |
|---|---|---|
| 주기 | 일 · 주 · 순 · 월 | 고른 지표 중 **가장 거친 주기보다 촘촘하게는 못 고른다** (순 지표가 있으면 일·주 비활성, 월 지표가 있으면 월만). 집계는 지표마다 정해진 방식(가격·기온·환율 = 평균, 반입량·강수 = 합계) |
| 변환 (지표별) | 원값 · 지수(시작=100) · 전년 대비 % · 평년 대비 % · 이동평균(3) | 단위가 다른 지표를 한 차트에 겹치면 자동으로 **지수**를 권한다. 두 축(이중 y축) 차트는 만들지 않는다 |
| 시차 (지표별) | −90 ~ +90일 (순 주기면 −9 ~ +9순) | "경매가를 14일 앞당겨 소매가와 겹쳐 보기". 표·차트·해석 모두에 반영 |
| 기간 | 1년 · 3년 · 전체 · 직접 | 지표마다 시작이 달라 겹치는 기간을 표시 |

### 4.4 그리기 — 차트 6종
| 차트 | 축 | 쓰는 곳 | 라이브러리 |
|---|---|---|---|
| **시계열 겹쳐 보기** | x 날짜, y 값(같은 변환끼리) | 흐름 비교, 시차 확인 | Recharts |
| **산점도** | x 지표 A, y 지표 B, 색 = 연도 또는 계절 | 두 지표 관계, 상관계수 표시 | Recharts |
| **3D 산점도** | x · y · z 지표 직접 선택, 색 = 네 번째 지표 또는 계절 | 세 지표가 함께 만든 상황 (목업의 '상황 공간') | Plotly (이 페이지에서만 로드) |
| **평행 좌표** | 고른 지표마다 세로축 하나 | 조건 조합 탐색 — 축 구간을 끌면 그 조건의 날만 남는다 (목업의 '이종 변수 탐색기') | Plotly |
| **시차 상관 히트맵** | 행 = 지표, 열 = 시차(0~12순), 색 = 기준 지표와의 상관 | 어떤 지표가 몇 순 뒤 가격에 반영되나 | Plotly |
| **가격 지형도** | x 한 해 중 시기(36순), y 연도, 높이·색 = 값 | 계절성과 이상했던 해 (목업의 '3D 가격 지형도') | Plotly |

마우스를 올리면 값·날짜가 나오고, 차트마다 표로 보기(아래 표)와 같은 값을 쓴다.

### 4.5 거르기 — 조건
- "반입량 평년 대비 ≤ −15% 그리고 기온 평년 대비 ≥ +1.5℃" 처럼 지표별 범위를 건다 (평행 좌표에서 끌어도 같은 조건이 된다)
- 조건에 맞는 날(순)은 **모든 차트에서 함께 강조**되고, 표는 그 행만 걸러진다
- 해석에 "조건에 맞는 순 n개 — 그때 양파 소매가 평년 대비 중앙값 +12%" 처럼 사례 수와 함께 요약

|---|---|
| CSV 받기 | 지금 화면의 정렬된 표 그대로(주기·변환·시차·조건 반영). 맨 위에 지표별 **출처 · 단위 · 변환** 설명 줄 |
| 이미지 | 지금 차트를 PNG 로 |

| 저장 (로그인) | 내 분석 목록 (2차) |

### 4.7 시작 템플릿
빈 화면 대신 바로 열리는 출발점. 품목은 열 때 고른다(기본 양파).

| 템플릿 | 지표 · 설정 | 주로 |
|---|---|---|
| 도매가 → 소매가 | 소매가 + 경매가(또는 KAMIS 도매), 지수, 시계열 + 시차 상관 | 소매상 |
| 반입량과 경매가 | 경매가 + 반입량(평년 대비), 순, 산점도 | 도매상 |
| 날씨와 가격 | 소매가(평년 대비) + 산지 기온·강수(평년 대비), 순, 시계열 + 평행 좌표 | 도매상 · KAMIS 직원 |
| 품목끼리 비교 | 여러 품목 소매가, 지수, 시계열 | KAMIS 직원 |
| 상황 공간 3D | 반입량 · 기온 · 소매가(모두 평년 대비), 순, 3D 산점도 | 모두 |
| 가격 지형도 | 소매가, 지형도 | 모두 |

### 4.8 잘못 읽히지 않게
- 두 축 차트는 만들지 않는다(단위가 다르면 지수 또는 차트 나누기)
- 주기가 다른 지표는 자동으로 맞추고, 무엇을 어떻게 맞췄는지 표 머리에 적는다
- 상관·조건 요약에는 **사례 수**를 붙이고 "함께 움직였다는 뜻일 뿐 원인은 아니다" 를 둔다
- 지표마다 기간이 다르면 겹치는 기간만 계산에 쓴다고 표시한다
- 기온·강수의 전년·평년 대비는 비율이 아니라 **차이(℃·mm)** 로 — 마른 철 강수는 평년이 0 에 가까워 비율이 수천 %로 튄다 (PR3 화면 확인에서 발견)
- 합계 지표(강수·반입량)를 더 긴 주기로 묶을 때 **아직 다 차지 않은 마지막 칸은 뺀다** — 순 중간의 합계는 실제보다 작게 보인다
- 주기를 바꾸면 시차를 비슷한 날 수로 옮긴다(14일 → 1순). 시차 값이 '칸' 단위라 그대로 두면 14일이 14순이 된다

## 5. 데이터 설계

### 5.1 통합 시계열 — 테이블 2개
모든 지표를 같은 모양(지표 · 날짜 · 값)으로 모아 두면 API 하나, 화면 하나로 어떤 조합이든 그릴 수 있다.

```sql
series_catalog (
  series_id   VARCHAR(80) PK,   -- 'retail:양파', 'supply:배추', 'station_temp:261'
  name        VARCHAR(100),     -- '양파 소매가'
  item        VARCHAR(30),      -- '양파' (거시 지표는 NULL)
  category    VARCHAR(20),      -- 가격 · 수급 · 기상 · 거시 · 관심도
  source      VARCHAR(80),      -- 'KAMIS 소매 · 서울 경동·복조리 평균'
  unit        VARCHAR(30),      -- '원/1kg', '톤', '℃', 'mm', '원/달러', '2020=100'
  freq        VARCHAR(10),      -- daily · soon · monthly (가장 촘촘한 주기)
  agg         VARCHAR(10),      -- mean · sum (주기를 거칠게 바꿀 때)
  first_date, last_date DATE, n_points INT, sort_order INT, updated_at TIMESTAMP
)
series_value (
  series_id VARCHAR(80), obs_date DATE, value DOUBLE,
  PRIMARY KEY (series_id, obs_date)
)
```
- 순 주기 지표는 그 순의 첫날(1·11·21일)에, 월 지표는 1일에 둔다
- 규모: 지표 약 50개 × 날짜 최대 4,600 → 수십만 행. 지표별로 통째 다시 쓴다(멱등)

### 5.2 지표 목록 v1 (지금 있는 데이터로)
품목 목록은 원본 테이블에 있는 값을 그대로 읽는다(코드에 품목을 적지 않는다).

| 분류 | series_id | 내용 · 출처 | 주기 · 집계 | 기간 |
|---|---|---|---|---|
| 가격 | `retail:{품목}` | KAMIS 소매, 서울 경동·복조리 평균 (`retail_market_price`) | 일 · 평균 | 2014-07~ |
| 가격 | `wholesale:{품목}` | KAMIS 도매 '가락도매'(중도매인 판매가) (`wholesale_market_price`) — 애호박·시금치·오이 | 일 · 평균 | 2014~ |
| 가격 | `auction:{품목}` | 가락시장 경매가 상, 농넷 (`agri_price` + 레포 `hist_daily_*.csv`) — 배추·양파·홍고추·양배추 등 | 일 · 평균 | 2013~ (홍고추 2001~) |
| 수급 | `supply:{품목}` | 가락시장 반입량 (`supply_data` 일별 합 + 레포 `hist_supply*.csv` 순별) | 순 · 합계 | 2018~ |
| 기상 | `station_temp:{지점}` · `station_rain:{지점}` | 기상청 ASOS 관측소 11곳 일 평균기온 · 일강수량 (`station_weather_data`) | 일 · 평균/합계 | 수집 시작~ |
| 기상 | `area_temp:{지점}` · `area_rain:{지점}` | 산지 기상 순별 (레포·서버 `weather_*.csv` — 해남·태백·밀양) | 순 · 평균 | 2018~ |
| 거시 | `fx:usd` · `fx:cny` | 원/달러 · 원/위안 (`hist_exchange.csv` 순 + `exchange_rate_daily`) | 순 · 평균 | 2018~ |
| 거시 | `oil:diesel` | 오피넷 자동차용 경유 전국 평균 (`oil_price`) | 일 · 평균 | 수집 시작~ |
| 거시 | `cpi:{품목}` · `ppi:{품목}` | KOSIS 품목별 소비자·생산자 물가지수 (`cpi_data`·`ppi_data`) | 월 · 평균 | 수집 시작~ |
| 관심도 | `search:{검색어}` | 네이버 데이터랩 검색량 (`search_trend`) | 일 · 평균 | 2016~ |

2차 후보: 판매처별 소매가(`retail_market:{품목}:{판매처}`), 소매·도매 예측값(`forecast:*`), 지역별 KAMIS 소매가.

- 지표 종류마다 **읽기 함수 하나**(원본 테이블·CSV → 날짜별 값). 품목·지점·검색어는 원본에서 찾는다
- 지표마다 `series_value` 를 통째 바꾸고 `series_catalog` 의 기간·개수를 갱신한다. 원본이 비면 그 지표는 건너뛴다(기존 값 유지)
- 테스트: 가짜 원본으로 각 읽기 함수, 순·월 날짜 규칙, 두 번 돌려도 같은 결과, 품목 이름이 파일에 없음

### 5.4 API (백엔드)
| 메서드 | 경로 | 응답 |
|---|---|---|
| GET | `/api/series/catalog` | `[{id, name, item, category, source, unit, freq, agg, firstDate, lastDate, points}]` |
| GET | `/api/series/data?ids=a,b,c&from=2018-01-01&to=2026-10-04` | `{series: [{id, points: [["2026-10-01", 1234.0], …]}]}` — 원래 주기 그대로, 최대 8개 |

주기 맞추기·변환·시차·상관·조건은 **화면에서 계산**한다. 데이터가 작아(지표 8개 × 수천 점) 바꿀 때마다 다시 받지 않아도 되고, 백엔드는 품목·지표를 몰라도 된다.

## 6. 프론트 설계

- 색은 tailwind 토큰 + 차트용 범주 색 8개(고른 순서대로 고정)
