## 목적

공모전(2026 KAMIS 활용사례, Open API 부문) 심사에서 **KAMIS Open API 를 실제로 쓰고 있다는 것이 홈에서 바로 보이게** 한다.
홈의 "AI 농산물 가격 예측 모델" 설명 섹션 자리에 KAMIS 서울 소매가 현황을 보여 주고, 소매 예측 모델이 나오면(KAMIS 과거 자료 회신 후) 같은 자리에 "다음 순 예상가"를 채운다.

**성공 기준**
- 홈에 들어오면 양파·붉은고추·양배추의 서울 소매가 현황과 출처(KAMIS Open API · 서울 · 상품)가 바로 보인다
- 모바일 폭에서도 깨지지 않는다
- 예측이 없는 지금도 빈칸처럼 어색하지 않다

**범위 밖**
- 소매 예측 모델 자체 (과거 자료 회신 후 별도 작업)
- 기존 모델 설명 내용의 새 자리 (문서로 둘지 페이지로 만들지 후속 작업에서 정한다)

## 데이터

`retail_price` (#29): 품목별 일별 서울 평균 소매가, 상품 등급, 2025-01-02 ~, 매일 09:30·17:30 KST 갱신.
품목·단위: 양파 1kg / 붉은고추 100g / 양배추 1포기.

## 백엔드

`PriceController`(`/api/price`) 에 조회 전용 엔드포인트 두 개를 더한다. 계산은 새 `RetailPriceService` 에 두고, 순 판정·순 평균·요약은 DB 와 떨어진 순수 함수로 만든다.

### `GET /api/price/retail/summary` — 카드용

```json
[
  {
    "itemName": "양파",
    "unit": "1kg",
    "latestDate": "2026-09-23",
    "latestPrice": 1841,
    "prevSoonAvg": 1880,
    "changePct": -2.1,
    "prediction": null
  }
]
```

- 품목 순서는 양파 · 붉은고추 · 양배추 고정 (`KamisRetailService.TARGET_ITEMS` 순서)
- `latestPrice`: 가장 최근 조사일 값
- `prevSoonAvg`: 최근 조사일이 속한 순의 **바로 앞 순** 평균. 그 순에 조사일이 없으면 더 앞 순으로 가지 않고 `null`
- `changePct`: `(latestPrice - prevSoonAvg) / prevSoonAvg × 100`, 소수 첫째 자리. `prevSoonAvg` 가 `null` 이면 `null`
- `prediction`: 지금은 항상 `null`. 모델이 생기면 `{ "target": "202610상순", "price": 1900 }`
- 데이터가 없는 품목은 `latestDate`·`latestPrice` 가 `null` 인 채로 목록에 남긴다 (카드 자리를 유지하려고)

### `GET /api/price/retail/series?itemName=양파&unit=daily|soon` — 차트용

```json
{
  "itemName": "양파",
  "unit": "1kg",
  "points": [ { "date": "2025-01-02", "label": "2025-01-02", "price": 2110, "days": 1 } ],
  "predictions": []
}
```

- 기간은 전체(2025-01 ~) 를 한 번에 준다. 일별 약 420점
- `unit=daily`: 조사일마다 한 점. `days` 는 1
- `unit=soon`: 순마다 한 점. `date` 는 순 첫날(1·11·21일), `label` 은 `2025-01 상순`, `price` 는 그 순 조사일 값의 단순평균(원 단위 반올림), `days` 는 조사일 수
- 순 판정: 1~10일 상순, 11~20일 중순, 21일~말일 하순 (기존 예측 모델과 같은 규칙)
- `predictions`: 지금은 빈 배열. 모델이 생기면 `[ { "date": "2026-10-01", "label": "2026-10 상순", "price": 1900 } ]` — **순별에서만** 채운다
- `itemName` 이 대상이 아니면 400, `unit` 이 둘 다 아니면 400

## 화면

새 컴포넌트 `KCSPfront/src/components/RetailPriceSection.jsx` 를 만들고 `Home.jsx` 에서는 기존 모델 설명 섹션 자리에 한 줄로 넣는다. 조회 함수 `getRetailSummary`·`getRetailSeries` 를 `api.js` 에 더한다.

```
┌ 서울 농산물 소매가 ─────────────────────────────────────┐
│ KAMIS Open API · 서울 평균 · 상품 등급 · 매일 갱신        │
│ [양파 1kg]        [붉은고추 100g]     [양배추 1포기]      │  ← 누르면 아래 차트가 바뀜
│  1,841원           2,105원             3,011원            │
│  지난 순 평균 대비 ▼2.1%  ...                            │
│  9/23 조사                                               │
│  다음 순 예측 · 준비 중                                  │
├──────────────────────────────────────────────────────────┤
│ 양파 소매가 추이                     [일별] [순별]       │
│ [ 차트 ]                           ─ 실제  ┈ 예측(순별만) │
└──────────────────────────────────────────────────────────┘
```

**카드 3장**
- 품목명 + 단위, 최근 가격, 조사일, "지난 순 평균 대비 ▲/▼ n%" (상승 `text-price-up` 빨강 · 하락 `text-price-down` 파랑 · 0 이면 기본색)
- 맨 아래 "다음 순 예측 · 준비 중" 회색 한 줄. `prediction` 이 오면 "다음 순(10월 상순) 예측 1,900원"
- 선택된 카드는 테두리 강조. 처음엔 첫 품목(양파) 선택
- 모바일: 카드는 한 줄에 3장이 안 들어가면 세로로 쌓는다

**차트** (recharts, 상세 화면과 같은 색·축 스타일)
- 제목 "{품목} 소매가 추이", 오른쪽에 [일별] [순별] 토글. 기본 **순별**
- 순별일 때만 예측선(점선)을 그리고 범례에 "예측" 을 넣는다. `predictions` 가 비면 범례의 예측 항목도 숨긴다
- 툴팁: 날짜 또는 순 라벨, "n원 / 단위", 순별이면 "조사 n일"
- 품목이나 단위를 바꾸면 그 조합을 다시 조회한다 (응답이 작아 캐시는 두지 않는다)

**상태**
- 불러오는 중: 카드·차트 자리 스켈레톤 (`animate-pulse`, 기존 화면과 같은 방식)
- 요약 조회 실패: 섹션 전체에 `StatusMessage` 오류
- 추이 조회 실패: 차트 자리만 오류, 카드는 그대로
- 품목에 데이터가 없음: 그 카드에 "데이터 없음", 차트는 빈 상태 안내

**걷어내는 것**
- `Home.jsx` 의 모델 설명 섹션과 상수 `DATA_SOURCES`·`PIPELINE_STEPS`·`MODEL_FEATURES`·`KEY_VARIABLES`
- 내용은 git 이력에 남는다. 어디로 옮길지는 `PROGRESS.md` 4.4 에 후속 작업으로 적는다
