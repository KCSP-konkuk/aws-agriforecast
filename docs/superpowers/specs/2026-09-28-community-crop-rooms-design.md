# 커뮤니티 개편: 품목방 · 다음 순 예측 투표 · 시세 브리핑

2026-09-28

## 목적

지금 커뮤니티는 유통업자용 일반 게시판(도매정보·소매노하우·구인구직·자유게시판)이고 글은 테스트 글 1개뿐이다. 공모전(2026 KAMIS 활용사례)에 맞게 **농산물 가격 데이터와 엮인, 실제로 쓸모 있는 커뮤니티**로 바꾼다.

- 품목마다 방을 두고, 방 맨 위에서 **"다음 순 가락 경매가가 오를까·비슷할까·내릴까"** 를 함께 예측한다
- 순이 끝나면 **참여자 다수 · AI · 실제** 를 나란히 보여 준다 (서비스 핵심인 AI 예측과 사람들의 감을 비교)
- 순마다 **시세 브리핑 글이 자동으로 올라와** 커뮤니티가 비어 보이지 않게 한다

**성공 기준**
- 커뮤니티에 들어오면 배추방이 열리고, 투표·지난 순 결과·글 목록이 한 화면에 보인다
- 로그인한 사람은 한 번 눌러 투표하고, 마감 전엔 바꿀 수 있다
- 순 첫날 브리핑 글이 품목마다 하나씩 자동으로 올라온다
- 사이트 기존 틀(헤더·초록 알약 탭·배경·글꼴)에 자연스럽게 섞이고, "AI 가 만든 티" 가 나지 않는다

**범위 밖**
- 보상(뱃지·칭호·순위) — 투표와 결과 비교만 먼저 하고 필요하면 나중에 붙인다 (사용자 결정)
- 소매가 기준 투표 — 소매 예측 모델이 생긴 뒤

## 구조

탭: **배추 · 양파 · 홍고추 · 자유** (기존 카테고리 4개와 "전체" 탭은 없앤다). 처음엔 배추.

- 품목방(배추·양파·홍고추 — AI 예측이 운영 중인 품목): 투표 카드 → 글 목록(맨 위 최신 브리핑 고정)
- 자유방: 글 목록만

게시글의 `category` 값이 곧 방이다: `배추` · `양파` · `홍고추` · `자유`. 기존 카테고리 값의 글은 앱 기동 시 `자유` 로 옮긴다(멱등 UPDATE). 지금 해당 글은 1개.

## 투표 규칙

**순**: 1~10일 상순 · 11~20일 중순 · 21일~말일 하순 (예측 모델·홈 소매가와 같은 규칙, 코드는 공용 유틸로 모은다)

- **대상**: 지금 순이 N 이면 **N+1 순의 가락 경매가 순 평균**(상 등급, `agri_price` 일별 값의 순 내 평균 — 상세 화면·AI 예측과 같은 가격)
- **기준가**: N 순의 경매가 평균
- **판정**: (N+1 평균 − N 평균) / N 평균 이 **+3% 초과 → 오른다**, **−3% 미만 → 내린다**, 그 사이 **비슷** (±3% 는 사용자 결정, 상수 하나로 둔다)
- **참여**: 로그인한 회원만, 품목·대상 순마다 한 사람 한 표. 마감 전엔 다시 눌러 바꿀 수 있다. 비로그인이 누르면 기존 로그인 안내(`LoginRequired`)
- **마감**: N 순 마지막 날 24:00 KST. 화면엔 D-day 로만 (예: 9/28 에 9월 하순이면 10월 상순 투표, D-2)
- **AI 예측**: N+1 순 예측은 N+1 첫날 새벽 배치가 처음 만든다. 투표 기간엔 존재하지 않으므로 따로 가리지 않는다. 결과 표의 AI 칸이 그때 채워진다
- **득표율은 참여자가 적어도 그대로** 보인다. 0표면 퍼센트 대신 빈 막대 + "첫 표를 기다려요" 상태

**지난 순 결과** (방마다 1개): 이미 끝난 가장 최근 순 T(= N−1). T 를 대상으로 했던 투표 집계와
- 참여자 다수 방향 (최다 득표 선택지, 동률이면 "갈림", 0표면 없음)
- AI 방향: T 의 예측가(`{item}_predictions`, 없으면 `{item}_backtest`) vs T−1 실제 평균
- 실제 방향: T 평균 vs T−1 평균
- 적중 표시: 참여자 다수·AI 각각 실제 방향과 같으면 적중
- 실제 평균에 필요한 가격이 없으면(수집 전) 그 칸은 비운다

## 시세 브리핑 (자동 글)

- 매 순 첫날(1·11·21일) **12:10 KST** — 일별 가격 수집(11:00, 전날분)이 끝난 뒤. 품목(배추·양파·홍고추)마다 1개
- 작성자: 시스템 계정 `agriforecast`(이름 "AgriForecast"). 앱 기동 시 없으면 만든다. 비밀번호는 로그인할 수 없는 임의값
- 글 구분: 게시글에 `KIND` 컬럼 추가(`USER` 기본 · `BRIEF`). 기존 행은 NULL → USER 로 취급
- 같은 품목·같은 순 브리핑이 이미 있으면 만들지 않는다(멱등, 제목으로 판별)
- 제목: `10월 상순 배추 시세 브리핑`
- 본문(템플릿, 숫자만 채움. 값이 없는 줄은 뺀다):
  ```
  지난 순(9월 하순) 가락시장 배추 경매가는 평균 13,210원(상, 10키로망대)으로 그 전 순보다 5.5% 내렸습니다.
  AI 는 이번 순(10월 상순) 평균을 13,900원으로 예측합니다. 지난 순보다 5.2% 높은 값입니다.
  지난 순 투표: 참여자 다수 '오른다' · AI '비슷' · 실제 '내린다'.
  ```
- 수동 실행: `POST /api/collect/community/brief` (다른 수집 트리거와 같은 위치)

## 백엔드

**테이블**
- `community_vote`: `ID`, `ITEM_NAME`(배추/양파/홍고추), `TARGET_SOON`(`202610상순`), `MEMBER_ID`(member_user.SEQ_NO_A010), `CHOICE`(`UP`/`SAME`/`DOWN`), `UPDATED_AT`. 유니크 (ITEM_NAME, TARGET_SOON, MEMBER_ID)
- `posts`: `KIND` VARCHAR(10) NULL 추가

**API** (`/api/community`)
- `GET /votes/{itemName}` — 로그인 선택(있으면 `myChoice`)
  ```json
  {
    "itemName": "배추",
    "target": { "code": "202610상순", "label": "10월 상순", "closesOn": "2026-09-30", "dday": 2 },
    "counts": { "UP": 69, "SAME": 36, "DOWN": 23 }, "total": 128, "myChoice": "UP",
    "last": {
      "code": "202609중순", "label": "9월 중순",
      "crowd": "UP", "ai": "UP", "aiPrice": 12882, "actual": "UP", "actualPrice": 13986,
      "crowdHit": true, "aiHit": true
    }
  }
  ```
  `last` 는 계산할 T 가 없으면 `null`, 각 필드는 값이 없으면 `null`
- `POST /votes/{itemName}` `{ "choice": "UP" }` — 로그인 필요(기존 규칙대로 `/api/community/**` POST 는 인증). 대상 순은 서버가 오늘(KST) 기준으로 정한다. 대상 아닌 품목·선택지는 400. 응답은 GET 과 같은 모양
- 게시글 응답(`PostResponse`)에 `kind` 추가. 목록 API 는 그대로(최신순) — 고정은 화면이 최신 BRIEF 1개를 맨 위로 올린다

**구성**
- 순 계산 공용 유틸 `Soon` (코드·라벨·시작일·끝일·이전/다음 순) — `RetailPriceService` 의 순 함수도 여기로 옮긴다
- `CommunityVoteService`: 투표 저장·집계·지난 순 결과 (순수 계산은 static 함수로 분리해 테스트)
- `MarketBriefService` + 스케줄러: 브리핑 작성
- 시스템 계정·카테고리 이관: 기동 시 1회 실행하는 초기화 컴포넌트
- 실제 순 평균: `agri_price` 일별 값 평균 (`PriceService`/리포지토리 재사용)
- AI 예측가: `PredictionService` 의 테이블 매핑 재사용

## 화면 (A안 — 카드 톤, 글자 굵기 낮춤)

사이트 공통 요소(헤더·큰 페이지 제목·초록 알약 탭·배경·Work Sans/Noto Sans KR·등락 색)는 그대로. 커뮤니티 안쪽만 바꾼다.

**원칙** (레퍼런스: Polymarket·토스·Reddit, 사용자 피드백)
- 점으로 이어 붙인 작은 회색 설명 줄, 제목 위 라벨, 부제는 쓰지 않는다. 정보는 구조로 (마감 = D-day, 지난 결과 = 작은 표)
- 글자 단계는 제목·본문·숫자 셋. 굵기: 제목 600 · 숫자 500 · 본문 400. 12px 이하 글씨는 쓰지 않는다
- 색은 등락(빨강 ▲/파랑 ▼)과 "내가 고른 선택지", 브랜드 초록(탭·버튼·댓글 수·적중)에만
- 카드 안에 카드를 넣지 않는다. 글 목록은 구분선 리스트

**페이지**: 제목 "커뮤니티" → 알약 탭 4개 → (품목방) 투표 카드 → "{품목} 이야기" + 글쓰기 → 글 목록

**투표 카드**(흰 카드)
- 머리: "10월 상순 배추값, 오를까요?" + 오른쪽 D-day 표시
- 선택지 3칸 가로 배치: "▲ 오른다 / ― 비슷 / ▼ 내린다" + 득표율 큰 숫자, 칸 아래에서 득표율만큼 옅게 차오르는 채움. 내가 고른 칸만 빨강/파랑/회색 테두리로 강조
- 0표: 퍼센트 대신 "첫 표를 기다려요"
- 아래 구분선 뒤 "9월 중순 결과" 작은 표: 참여자 예측 / AI 예측(가격) / 실제(가격) + 적중
- 모바일: 선택지 3칸은 유지(가로), 글자 크기만 줄임

**글 목록**(흰 카드, 구분선 리스트): 최신 브리핑 1개를 맨 위(옅은 초록 배경·초록 제목), 이어서 사용자 글. 한 줄에 제목 + 댓글 수(초록) · 오른쪽 시간. 작성자는 목록에서 뺀다(상세에선 그대로)

**글쓰기·수정**: 카테고리 선택지를 4개 방으로 바꾸고, 방에서 누른 글쓰기는 그 방을 기본값으로

## 테스트

- 백엔드 (외부 의존 없음, CI 목록에 추가)
  - `Soon`: 경계(10·11·20·21·말일), 다음·이전 순(월·연 경계), 라벨, 마감일
  - 방향 판정: +3.0% 는 비슷, +3.01% 는 오른다, −3% 경계
  - 집계: 참여자 다수(동률 → null, 0표 → null), 적중 판정, 값 없는 칸 null
  - 투표 입력 검증: 대상 아닌 품목·선택지 → 400, 같은 사람 재투표는 갱신
  - 브리핑 본문: 값 없는 줄 빠짐, 같은 순 중복 생성 안 함
- 프론트: `npm run build`, 로컬 화면 확인(데스크톱·375px) — 백엔드 API 를 임시 서버로 붙여 본다
- 배포 후: 투표 → 새로고침 후 유지, 로그아웃 상태 안내, 브리핑 수동 실행 1회
