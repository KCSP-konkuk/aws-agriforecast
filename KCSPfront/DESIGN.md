# AgriForecast 디자인 기준

2026-10 로컬 UI 개편안. 첫 시안 검토 후 생성 농산물 사진과 반복되는 민트 카드를 제거했다. 흰 바탕, 큰 타이포그래피, 얇은 구분선과 실제 데이터 중심으로 구성한다. 기존 품목·지표·분석 기능과 데이터의 의미는 유지한다.

## 화면 원칙

- 첫 화면은 서비스 설명과 실제 데이터 규모, 가격 전망, 질문별 분석, 데이터 목록 순서로 구성한다.
- 소매와 도매는 가격 기준·단위·예측 기간을 명시한다. 이름이 다른 붉은고추/홍고추도 같은 품목의 관련 화면으로 연결한다.
- 품목 상세는 가격과 기준일을 먼저, 설명·차트·표를 뒤에 둔다. 모든 품목과 지표를 계속 선택할 수 있어야 한다.
- 분석 작업대는 데스크톱 왼쪽에 지표 설정, 오른쪽에 차트와 표를 둔다. 모바일 설정은 차트 위에서 펼친다.
- 긴 정보는 펼치기로 접근하게 한다. 템플릿 8개, 이벤트 전체, 데이터 표 전체와 CSV를 유지한다.
- 본문은 짧고 구체적으로 쓴다. 상세 데이터 출처와 거래 단위는 줄이거나 감추지 않는다.

## 레이아웃과 컴포넌트

- 일반 최대 폭 1440px, 작업대 1600px, 읽기·글쓰기 900px. 바깥 여백은 모바일 16px, 태블릿 28px, 데스크톱 40px.
- 공통 스타일은 `src/index.css`의 page-shell, panel, page-heading, button-primary, button-secondary, crop-tabs에 둔다.
- 공통 패널은 흰색·8px 모서리·옅은 테두리로 구분한다. 홈은 박스 대신 구분선을 사용하고, 품목 전망은 정렬된 행으로 비교한다. 사진은 사용하지 않는다.
- 품목은 둥근 선택 버튼, 차트·기간 선택은 세그먼트로 표현한다. 선택 상태는 aria-pressed로도 제공한다.
- 주요 버튼과 입력은 약 40–48px 높이, 포커스 테두리는 항상 유지한다. 아이콘만 있는 버튼에는 접근 가능한 이름이 필요하다.
- 화면 전체에는 가로 스크롤이 없어야 한다. 많은 탭과 데이터 표만 영역 안에서 가로로 넘긴다.
- 차트 축은 최소 12px, 모바일 눈금은 자동 간격을 사용한다. 실제값 실선과 예측값 점선을 구별한다.
- 로딩·오류·빈 결과를 구별한다. 오류를 정상 데이터처럼 표현하지 않는다.

## 검증

`npm run build`, `npm run lint`, `npm test`를 실행한다. 브라우저에서는 데스크톱과 모바일에서 전체 경로, 품목 전환, 메뉴 키보드 조작, 작업대 차트 전환을 확인한다. 로그인 전용 화면의 디자인 검증은 로컬 응답으로 할 수 있으나 실제 인증·저장 성공 검증과 구별해 기록한다.

사진의 생성 정보와 이번 개편 검토 기록은 [UI_REFRESH.md](UI_REFRESH.md)를 참고한다.
